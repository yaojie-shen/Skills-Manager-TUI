## 查看目标

```sh
skills agents catalog
skills agents list
```

`skills agents catalog` 列出内置 Agent 路径；`skills agents list` 显示当前 Library 已配置的目标。默认配置包含 Claude 和 Codex。Agent 条目描述目标目录，并不表示对应的 Agent 已安装。

需要时可注册自定义目标：

```sh
skills agents add cursor
skills agents add custom --dir /path/to/skills
```

## 预览并部署

部署命令使用 `skills list` 返回的 Library key。

```sh
skills deploy hello-skill --agent claude --dry-run
```

预览只报告计划创建的链接，不修改目标。以下输出表示计划没有冲突。如果已有其他 Library 技能使用相同的目标名称，dry run 会改为报告冲突：

```text
link   claude/hello-skill -> /path/to/library/hello-skill
dry run: 1 change(s) not applied
```

执行部署：

```sh
skills deploy hello-skill --agent claude
```

```text
link   claude/hello-skill -> /path/to/library/hello-skill
applied 1 change(s)
```

至少指定一个 `--agent`，或使用 `--all-agents` 选择所有已配置 Agent，两者不能混用。显式指定内置 Agent 时无需注册，使用与 TUI 选择器相同的目的地；`--all-agents` 不包含尚未配置的目录条目。

删除受管理的链接，同时保留 Library 技能：

```sh
skills undeploy hello-skill --agent claude --dry-run
skills undeploy hello-skill --agent claude
```

## `--local` 与 `--project` 如何改变作用域

CLI 和 TUI 都按 `--root` → `$SKILLS_HOME` → 指针文件选择同一个 Library。`--project DIR` 只选择项目部署目的地，`--local` 使用当前目录。安装、tag 和 preset 仍修改中心 Library。

```sh
skills --root /path/to/library --project /path/to/project deploy hello-skill --agent claude
skills --local install ./source --deploy codex
```

项目目标与 TUI 选择器使用相同的首选目录：Claude 为 `<project>/.claude/skills`，Codex 为 `<project>/.agents/skills`，其中保存指向中心 Library 的链接。在项目范围显式指定内置 Agent 无需先注册。`--all-agents` 仅使用配置中的目标，并映射到项目；项目外的自定义目标会被排除。项目范围下 `agents add` 将项目目标注册到中心配置。所有路径（包括已有符号链接的祖先）必须在项目内部。`--local` 与 `--project` 不能同时指定。

**兼容说明：**旧版 CLI 会通过这两个参数打开独立的 `<project>/.agents/skills` 库，现在不再自动切换。若要继续使用旧库，请显式指定 `--root /path/to/project/.agents/skills`。现有文件不会被移动或删除。

## 链接直接引用 Library 内容

部署名称取自 `SKILL.md` frontmatter，而不是 Library 目录名。如果两个技能声明了同一个名称，同一 Agent 目标中不能同时存在两者。预览会报告冲突；`--same-name replace` 只授权替换这项声明名冲突。

部署会创建指向 Library 的实时链接。通过链接编辑会修改 Library 中的副本，Library 更新也会立即反映到已链接的 Agent。部署可以创建缺失的 Agent 目录。如果目标与 Library 重叠、路径经过符号链接解析，或目标不是目录，程序会将其归类为只读并跳过。这里的“只读”不检查操作系统写权限位。断链会一直保留，直到你明确清理或修复。

在 TUI 的 Agents 页面中，依次选择 Agent、作用域和部署组。激活尚未部署或只部署了部分成员的组，会部署其中所有成员。激活已全部部署的组，则会取消所有成员的部署。`0/0` 不执行操作，展开 `+N` 只显示隐藏的组。

只改变 Agent 部署状态不会触发根目录 Git 备份。[健康检查与修复](../health/)说明断链、副本遮挡和外部条目；[根目录备份与同步](../sync/)说明 Library 写入策略。

## 选择部署冲突

CLI 与 TUI 使用相同选择：保留某个 Library 技能、保留 Agent 自有内容，或全部不保留。先预览：

```sh
skills deploy review --agent claude --dry-run --json
skills deploy review --agent claude --choose claude/review=skill:review --archive-conflicts
```

预览的 `choices` 数组列出每组的 `selector` 和候选 `value`。为每组重复传入 `--choose SELECTOR=VALUE`，使用列出的原值（`skill:KEY`、`entry:FILENAME` 或 `none`）。共享物理目录只需一个选择。未知、遗漏或重复的选择在写入前报错。排除 Agent 自有内容时必须加 `--archive-conflicts`，内容会移动到 Agent 技能目录旁的 `.skills-manager-backups`；Library 技能目录始终保留。执行前与 TUI 一样重新校验状态。

preset 部署和 `install --deploy` 同样支持这些选择。若安装成功但后续部署失败，已安装的技能保留；用 `deploy --dry-run` 预览后再部署。`--same-name replace` 仍只处理托管链接替换，不能与 `--choose` 混用。

显式解决冲突时，JSON 包含选择值和完成 `message`，`applied` 为 null、`actions` 为空，因为共享流程会重新推导执行计划。普通部署继续提供动作列表和数量。
