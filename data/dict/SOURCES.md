# Dictionary sources

Query expansion looks a word up in each table below and, when it finds an
equivalent in the other language, adds it as a weaker alternative match.
Tables are generated by `scripts/build-dictionary.py`; do not edit by hand.

Format: `english<TAB>中文1|中文2`, one line per English term, sorted.
Both lookup directions are derived from this at load time.

| table | entries | source | license | filter |
|-------|---------|--------|---------|--------|
| `tech.tsv.gz` | 26,907 | [Microsoft Terminology Collection](https://www.microsoft.com/language/terminology), `CHINESE (SIMPLIFIED).tbx` | [MS-PL](LICENSE-MS-PL.txt) | drop product names, phrases over 3 words, Chinese over 12 chars, entries whose Chinese side is not mostly Han |
| `common.tsv.gz` | 27,472 | [ECDICT](https://github.com/skywind3000/ECDICT), `ecdict.csv` | [MIT](LICENSE-ECDICT.txt) | BNC/COCA rank 1000–30000, no proper nouns, at most 2 senses per word, each 2–6 Han characters |

Why the frequency band starts at 1000: words above that rank average about six
Chinese senses each (`operation`, `cut`, `serve`) and carry no discriminating
value in a query, so including them would only add false matches. Precision
improves further down the list — by rank 30000 the average is two senses.

Why the tables are separate rather than one file with a source column: the same
English word often means unrelated things in each register, and the two senses
deserve different weights. `tee` is 受信任执行环境 in the terminology table and
发球区 in the general one; merging would force a single weight on both. Keeping
them apart also costs less space than adding a column to every line.

Weights live in `config.toml` under `[search.dictionaries]` (`tech`, `common`,
`user`), so they can be tuned without regenerating any data. Zero disables a
source. A user table in the same format at `<skills>/.skills-meta/dictionary.tsv`
is loaded on top with the highest weight.
