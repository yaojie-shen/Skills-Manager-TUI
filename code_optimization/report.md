# TUI 操作延迟优化报告

日期：2026-09-09。完成两轮优化；基线为本次改动前的工作区，包含此前外部变化自动刷新功能。

## 测量方法

- macOS 26.5.2、arm64，Rust 1.98.0，release 构建。
- 300 个有基线哈希的 skill，放在 `repos/fixture/`；每个包含 SKILL.md 和 16 个 16 KiB 文件，payload 合计 75 MiB。
- 所有写入使用自动清理的临时 root 和虚构 agent 目录。没有修改真实的技能库或部署路径。
- 每轮单独启动测试进程；基线和最终版本各串行运行三次，表中为中位数。没有清空系统文件缓存，因此不是冷磁盘测试。
- 启动计时从 App 初始化到 TestBackend 首帧完成，包含扫描、搜索初始化和渲染，不包含 fixture 创建、编译或终端进程启动。
- 操作总延迟包含写操作、后台完整扫描和下一帧渲染。preset 表示对 50 个 skill 记录安装原因并部署/卸载，不包含交互式创建 preset 的输入时间。
- 普通安装/卸载通过相同共享操作闭包测试；最终删除测试经过真实确认事件和后台任务。不要把 `*_dispatch_ms` 当作所有页面的实际键盘响应时间：原 preset 页面已使用后台任务。
- 这些数据衡量本地管理流程，不包含 Git 克隆、远端下载、网络延迟。

## 结果：300 个 skill

| 操作 | 基线 ms | v1 ms（单次） | v2 ms（中位数） | 总耗时减少 |
|---|---:|---:|---:|---:|
| 启动首帧 | 1290.5 | 1260.1 | 612.8 | 52.5% |
| 安装 preset（50 个 skill） | 2377.1 | 1320.8 | 715.1 | 69.9% |
| 卸载 preset | 2347.5 | 1380.0 | 709.5 | 69.8% |
| 安装一个 skill 的链接 | 2312.4 | 1323.0 | 720.7 | 68.8% |
| 删除一个 skill 的链接 | 2283.7 | 1292.5 | 715.4 | 68.7% |
| 删除一个 skill 及刷新 | 2323.9 | 1296.7 | 707.5 | 69.6% |

## 第一轮：减少重复工作

1. 为链接规划提供专用的实时扫描：保留目录、文档、元数据、目标和 shadow 内容比较，跳过与部署无关的基线校验及重命名推断。完整 UI/Health 扫描仍执行内容校验。
2. 混合目标批操作复用一次规划快照，避免每个 agent 再扫描整个 root；写入时仍检查目标和安装原因。
3. Agents 页面在首次进入或快照失效后刷新，避免打开 Library 时初始化隐藏页面；启动入口也不再重复初始化 launch directory。

## 第二轮：限制并行读取、避免阻塞输入

1. 完整扫描的基线校验最多使用四个工作线程，哈希只在本次扫描内共享，不引入跨扫描的过期内容缓存。
2. 哈希按 64 KiB 分块读取，保留原有 v1 哈希格式、忽略规则及软链接处理方式。
3. 删除 skill、清理无效目录和确认卸载转到后台。执行时可继续浏览，其他写操作被明确阻止；完成后保留期间新打开的对话框。
4. 完整扫描携带扫描前的轮询指纹，避免自身写操作随后又触发一次相同扫描，同时保留对扫描期间外部变化的检测。

## CPU 与内存

- 基线：进程峰值 RSS 44.14 MiB；CPU 时间 6.18 秒。
- v1：进程峰值 RSS 41.27 MiB；CPU 时间 4.45 秒。
- v2：进程峰值 RSS 41.97 MiB；CPU 时间 4.65 秒。

CPU 和 RSS 由父进程 `getrusage(RUSAGE_CHILDREN)` 读取，包含 fixture 创建、全部测量操作和清理，不是单次操作的内存增量；RSS 为这一组子进程的高水位。并行读取最多四路，可能对慢盘、网络文件系统或其他磁盘负载产生不同影响。

## 验证

- `cargo test --locked --all-targets`：211 项通过，1 个性能基准默认忽略。
- `cargo clippy --locked --all-targets -- -D warnings`、`cargo fmt --all -- --check`、release 构建通过。
- 新增回归：链接规划不读取无关基线，但仍比较 shadow 内容；并行与串行扫描结果一致且后续编辑可见；分块哈希与原格式一致；后台工作时导航可用、并发写入被阻止、新对话框不被关闭。
- 既有部署冲突、共享目标、删除、软链接保护、更新和撤销测试继续通过。

## 重现

```sh
cargo test --locked --release --bin skills representative_tui_latency -- --ignored --nocapture
# 使用上一条命令输出中的测试可执行文件路径：
python3 code_optimization/measure.py target/release/deps/skills-<hash> --runs 3
```

设置 `SKILLS_BENCH_COUNT=1000` 可测量更大的临时库。原始测量保存在本目录 JSON 文件中；优化代码位于 src/，基准位于 src/tui/latency_bench.rs。
